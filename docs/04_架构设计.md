### 模块间协作关系说明

| 模块 | 输入 | 输出 | 协作对象 |
|------|------|------|----------|
| ① Hook层 | 内核内存管理函数调用 | 内存分配/释放事件 | ②策略引擎、④监控系统 |
| ② 策略引擎 | 策略注册请求、Hook事件 | 策略执行结果 | ③内置策略 |
| ③ 内置策略 | 策略调用 | 优化动作 | 无（独立实现） |
| ④ 监控系统 | Hook事件 | 监控统计数据 | ⑤分析引擎 |
| ⑤ 分析引擎 | 监控统计数据 | 分析结果（热点、瓶颈） | ⑥优化引擎 |
| ⑥ 优化引擎 | 分析结果 | 优化动作、告警 | ⑦接口层 |
| ⑦ 接口层 | 用户请求 | 配置、统计、分析结果 | 所有模块 |

## 3. 功能模块执行流程

### 3.1 功能一：Hook层 - Buddy分配拦截流程

**功能说明**：拦截Buddy System的`alloc_pages()`和`__free_pages()`函数，在分配和释放页面时介入。

**执行流程**：

```
开始
  │
  ▼
应用程序调用 alloc_pages(order=2, gfp=GFP_KERNEL)
  │
  ▼
进入内核空间
  │
  ├──────────────────────────────────────────────────────────┐
  │ Hook层：kprobe 拦截函数入口                              │
  │ ────────────────────────────────────────────────────── │
  │ 1. 调用 buddy_alloc_entry()                            │
  │ 2. 将参数（order, gfp）保存到per-CPU缓存               │
  │ 3. 调用策略引擎：buddy_pre_alloc(order, gfp, nid)      │
  │    → 策略可能修改gfp，强制使用本地NUMA节点            │
  │ 4. 返回 0（继续执行原函数）                             │
  └──────────────────────────────────────────────────────────┘
  │
  ▼
执行原始 alloc_pages() 函数
  │
  ├──────────────────────────────────────────────────────────┐
  │ Buddy System 原有逻辑                                    │
  │ ────────────────────────────────────────────────────── │
  │ 1. 根据gfp_mask选择NUMA节点                            │
  │ 2. 从Buddy System分配order阶的页面                      │
  │ 3. 返回 page 指针                                       │
  └──────────────────────────────────────────────────────────┘
  │
  ▼
返回 page 指针
  │
  ├──────────────────────────────────────────────────────────┐
  │ Hook层：kretprobe 拦截函数返回                           │
  │ ────────────────────────────────────────────────────── │
  │ 1. 调用 buddy_alloc_return()                           │
  │ 2. 从per-CPU缓存获取之前保存的参数                      │
  │ 3. 检查 page != NULL（分配成功）                        │
  │ 4. 调用策略引擎：buddy_post_alloc(page, order, gfp)     │
  │ 5. 更新统计数据：buddy_alloc_count++                    │
  │ 6. 通知监控系统：记录分配事件                            │
  └──────────────────────────────────────────────────────────┘
  │
  ▼
返回 page 指针给应用程序
  │
  ▼
结束
```

**涉及的关键数据**：
- per-CPU参数缓存（存储调用参数）
- Buddy分配统计计数器
- 策略引擎的当前策略指针

### 3.2 功能一：Hook层 - SLUB分配拦截流程

**功能说明**：拦截SLUB分配器的`kmalloc()`和`kfree()`函数，在小对象分配时介入。

**执行流程**：

```
开始
  │
  ▼
应用程序调用 kmalloc(size=100)
  │
  ▼
进入内核空间
  │
  ├──────────────────────────────────────────────────────────┐
  │ Hook层：kprobe 拦截 kmalloc 入口                        │
  │ ────────────────────────────────────────────────────── │
  │ 1. 调用 kmalloc_entry()                                │
  │ 2. 将 size 参数保存到per-CPU缓存                       │
  │ 3. 返回                                                │
  └──────────────────────────────────────────────────────────┘
  │
  ▼
根据 size 选择对应的 kmem_cache
  │
  ▼
调用 slub_alloc() 分配内存
  │
  ├──────────────────────────────────────────────────────────┐
  │ SLUB 分配器原有逻辑                                      │
  │ ────────────────────────────────────────────────────── │
  │ 1. 首先尝试从 per-CPU slab 获取对象（快速路径）        │
  │ 2. 如果 per-CPU slab 为空，从 slab cache 获取          │
  │ 3. 返回对象指针                                         │
  └──────────────────────────────────────────────────────────┘
  │
  ▼
返回对象指针
  │
  ├──────────────────────────────────────────────────────────┐
  │ Hook层：kretprobe 拦截 kmalloc 返回                     │
  │ ────────────────────────────────────────────────────── │
  │ 1. 调用 kmalloc_return()                               │
  │ 2. 从per-CPU缓存获取 size 参数                         │
  │ 3. 检查返回值 != NULL（分配成功）                       │
  │ 4. 调用策略引擎：slub_post_alloc(ptr, size)             │
  │ 5. 策略更新：检查是否命中 per-CPU 缓存                  │
  │ 6. 更新统计：slub_alloc_count++, cache_hit_ratio        │
  │ 7. 通知监控系统：记录分配事件                            │
  └──────────────────────────────────────────────────────────┘
  │
  ▼
返回对象指针给应用程序
  │
  ▼
结束
```

### 3.3 功能二：策略引擎 - Buddy策略调用流程

**功能说明**：在Buddy分配时调用当前注册的优化策略。

**执行流程**：

```
开始
  │
  ▼
Hook层调用：buddy_pre_alloc(order, gfp, nid)
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 策略引擎获取当前策略                                    │
│ ────────────────────────────────────────────────────── │
│ 1. 使用 RCU 读锁保护（读多写少场景）                  │
│ 2. 读取 engine->buddy_strategy（当前策略指针）          │
│ 3. 释放 RCU 读锁                                        │
└──────────────────────────────────────────────────────────┘
  │
  ▼
检查策略是否启用
  │
  ├──── 策略未启用 ────► 快速返回（0，继续原分配）
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 调用策略的 pre_alloc 回调函数                            │
│ ────────────────────────────────────────────────────── │
│ strategy->ops.pre_alloc(order, &gfp, &nid)            │
│                                                          │
│ 策略实现（例如 NUMA 感知策略）：                        │
│ 1. 获取当前 CPU 的 NUMA 节点                            │
│ 2. 检查 nid 是否与本地节点一致                          │
│ 3. 如果不一致，修改 gfp_mask 强制使用本地节点           │
│ 4. 返回 0（继续分配）                                   │
└──────────────────────────────────────────────────────────┘
  │
  ▼
更新策略统计信息
  │
  ├──── 策略调用失败 ────► 记录错误日志
  │
  ▼
返回结果给Hook层
  │
  ▼
结束
```

### 3.4 功能三：内置策略 - NUMA感知Buddy策略流程

**功能说明**：优先在本地NUMA节点分配内存，减少跨节点访问延迟。

**执行流程**：

```
开始
  │
  ▼
策略被调用：numa_buddy_pre_alloc(order, &gfp, &nid)
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 获取当前 CPU 的 NUMA 节点 ID                            │
│ ────────────────────────────────────────────────────── │
│ local_nid = numa_node_id()                             │
└──────────────────────────────────────────────────────────┘
  │
  ▼
检查原始节点与本地节点是否一致
  │
  ├──── nid == local_nid ────► 不需要修改，返回 0
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 检查本地节点是否有足够可用内存                          │
│ ────────────────────────────────────────────────────── │
│ 1. 获取本地节点的可用内存统计                          │
│   available = node_pages_available(local_nid)           │
│ 2. 需要的内存：needed = PAGE_SIZE << order              │
│ 3. 如果 available >= needed，可以强制本地分配            │
└──────────────────────────────────────────────────────────┘
  │
  ├──── 本地内存不足 ────► 不修改，使用原始分配
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 修改 gfp_mask 强制使用本地节点                          │
│ ────────────────────────────────────────────────────── │
│ 1. 清除 GFP_THISNODE 标志（如果存在）                   │
│ 2. 设置 GFP_NOWAIT 标志（避免等待）                     │
│ 3. 设置 nid 为 local_nid                                │
└──────────────────────────────────────────────────────────┘
  │
  ▼
更新统计信息
  │
  ├──── numa_local_alloc++（本地分配计数）
  ├──── numa_local_forced++（强制本地分配计数）
  │
  ▼
返回 0（继续分配）
  │
  ▼
结束
```

### 3.5 功能四：监控系统 - eBPF监控数据流

**功能说明**：使用eBPF零开销地收集内存分配事件和调用栈信息。

**执行流程**：

```
开始
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 模块初始化：加载 eBPF 程序                              │
│ ────────────────────────────────────────────────────── │
│ 1. 编译 eBPF 程序（使用 clang/llvm）                    │
│ 2. 调用 bpf_prog_load() 加载到内核                      │
│ 3. 创建 BPF map（用于存储统计和调用栈）                 │
│    - alloc_stats_map: 分配统计                          │
│    - stack_map: 调用栈快照                              │
│ 4. 附加 kprobe 到目标函数                               │
│    bpf_attach_kprobe(prog, "alloc_pages")               │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ eBPF 程序在内核空间执行（事件触发时）                   │
│ ────────────────────────────────────────────────────── │
│                                                          │
│ 1. 捕获事件：alloc_pages() 被调用                       │
│ 2. 读取调用栈：get_stack_id()                          │
│ 3. 计算调用栈的 hash 值                                 │
│ 4. 更新 BPF map：                                      │
│    - 在 alloc_stats_map 中增加该 stack 的调用次数        │
│    - 记录分配大小和时间戳                               │
│                                                          │
│ 5. 如果达到采样阈值，发送到 perf event ring buffer       │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 用户空间监控线程：定期读取 BPF map                      │
│ ────────────────────────────────────────────────────── │
│ 1. 调用 bpf_map_lookup_elem() 读取 map 数据              │
│ 2. 解析数据：按调用栈 hash 聚合统计                     │
│ 3. 更新内存中的热点统计结构                              │
│ 4. 调用分析引擎处理数据                                  │
│ 5. 睡眠一段时间，继续下一轮读取                          │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 模块退出：清理 eBPF 资源                                │
│ ────────────────────────────────────────────────────── │
│ 1. 分离 kprobe                                         │
│ 2. 销毁 BPF map                                         │
│ 3. 卸载 eBPF 空间                                      │
└──────────────────────────────────────────────────────────┘
  │
  ▼
结束
```

### 3.6 功能五：分析引擎 - 热点识别流程

**功能说明**：分析监控数据，识别Top-N热点调用堆栈。

**执行流程**：

```
开始
  │
  ▼
从监控系统获取数据
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 聚合按调用栈 hash 的统计信息                            │
│ ────────────────────────────────────────────────────── │
│ 对于每个 stack_hash：                                    │
│   - total_calls += stack_stats[hash].call_count           │
│   - total_bytes += stack_stats[hash].alloc_bytes          │
│   - 将 (stack_hash, stats) 加入列表                     │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 计算热点评分                                            │
│ ─�────────────────────────────────────────────────────  │
│ 对于每个调用栈：                                         │
│   - 访问频率得分 = call_count / total_calls              │
│   - 内存占用得分 = alloc_bytes / total_bytes            │
│   - 时间衰减得分 = exp(- (now - last_time) / decay)     │
│   - 综合得分 = 加权求和                                  │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 按综合得分降序排序                                        │
│ ────────────────────────────────────────────────────── │
│ 使用快速排序对热点列表进行排序                           │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 取 Top-N 热点（例如 Top 10）                            │
│ ────────────────────────────────────────────────────── │
│ 对于前 N 个调用栈：                                     │
│   - 解析符号表，获取函数名和行号                         │
│   - 格式化输出调用栈信息                                │
│   - 保存到全局热点列表                                  │
└──────────────────────────────────────────────────────────┘
  │
  ▼
通过接口层输出热点信息（/proc/smartmem/hotspots）
  │
  ▼
结束
```

### 3.7 功能六：优化引擎 - 自动调优流程

**功能说明**：根据分析结果自动调整优化策略参数。

**执行流程**：

```
开始
  │
  ▼
从分析引擎获取优化建议
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 检查是否需要调整策略                                    │
│ ────────────────────────────────────────────────────── │
│ 如果检测到：                                            │
│   - NUMA 远程访问率过高（> 30%）                         │
│   - SLUB 缓存命中率低（< 60%）                          │
│   - 内存碎片严重                                         │
└──────────────────────────────────────────────────────────┘
  │
  ├──── 不需要调整 ────► 返回
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 根据问题类型选择优化动作                                │
│ ────────────────────────────────────────────────────── │
│                                                          │
│ 问题1：NUMA 远程访问率过高                               │
│   → 调用 numa_balance_strategy_start()                  │
│   → 触发页面迁移到本地节点                               │
│                                                          │
│ 问题2：SLUB 缓存命中率低                                 │
│   → 调用 adaptive_slub_adjust_cache_size()              │
│   → 增加 per-CPU 缓存大小                               │
│                                                          │
│ 问题3：内存碎片严重                                       │
│   → 触发内核的 compact_memory()                         │
│   → 或者提前触发页面回收                                 │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 应用优化动作                                            │
│ ────────────────────────────────────────────────────── │
│ 1. 调用策略引擎切换或调整策略参数                        │
│ 2. 记录优化历史                                         │
│ 3. 更新统计信息                                         │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 通过 netlink 发送优化通知给用户空间                    │
│ ────────────────────────────────────────────────────── │
│ 1. 构建 netlink 消息                                    │
│ 2. 消息内容：优化类型、原因、执行的动作                  │
│ 3. 发送到订阅的守护进程                                 │
└──────────────────────────────────────────────────────────┘
  │
  ▼
结束
```

### 3.8 功能七：接口层 - procfs 读写流程

**功能说明**：提供procfs接口供用户空间读取配置和统计信息。

**执行流程**：

```
开始
  │
  ▼
模块初始化
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 创建 procfs 目录和文件                                  │
│ ────────────────────────────────────────────────────── │
│ 1. 创建目录：/proc/smartmem                            │
│    proc_mkdir("smartmem", NULL)                        │
│                                                          │
│ 2. 创建文件：                                           │
│    - /proc/smartmem/config    （配置信息）            │
│    - /proc/smartmem/stats      （统计信息）            │
│    - /proc/smartmem/hotspots   （热点信息）            │
│    - /proc/smartmem/policies    （策略信息）           │
│                                                          │
│ 3. 注册文件操作函数：                                   │
│    - .read: 读取回调函数                                │
│    - .write: 写入回调函数                               │
└──────────────────────────────────────────────────────────┘
  │
  ▼
用户空间读取 /proc/smartmem/stats
  │
  ▼
┌──────────────────────────────────────────────────────────┐
│ 读取回调函数被调用                                      │
│ ────────────────────────────────────────────────────── │
│ 1. 聚合 per-CPU 统计到全局统计                          │
│ 2. 格式化输出统计数据                                    │
│    例如：                                               │
│    buddy_alloc_count: 1234567                         │

## 5. 并发控制设计

**功能说明**：确保多核环境下的数据一致性和性能。

### 5.1 锁策略说明

| 数据结构 | 保护方式 | 说明 |
|----------|----------|------|
| 全局状态 `g_sm_state` | spinlock | 保护状态变更（启用/禁用） |
| 策略链表 | RCU + spinlock | RCU用于读取（读多写少），spinlock用于写入 |
| Hook状态 | atomic | 无锁原子操作 |
| per-CPU统计 | 无锁 | 每CPU独立，聚合时使用原子操作 |
| 监控数据 | RCU | 读多写少场景 |

### 5.2 策略读取流程

```
读路径（高频调用，使用RCU）
  │
  ▼
rcu_read_lock()                        // 开始RCU读临界区
  │
  ▼
strategy = rcu_dereference(engine->buddy_strategy)  // 读取策略指针
  │
  ▼
rcu_read_unlock()                      // 结束RCU读临界区
  │
  ▼
使用策略
```

### 5.3 策略切换流程

```
写路径（低频操作，使用spinlock）
  │
  ▼
spin_lock(&engine->buddy_lock)        // 获取写锁
  │
  ▼
old_strategy = engine->buddy_strategy
  │
  ▼
rcu_assign_pointer(engine->buddy_strategy, new_strategy)  // 原子更新指针
  │
  ▼
spin_unlock(&engine->buddy_lock)      // 释放写锁
  │
  ▼
synchronize_rcu()                      // 等待所有读者完成
  │
  ▼
释放旧策略（现在可以安全释放）
```

## 6. 性能优化设计

**功能说明**：确保Hook层的性能损耗最小。

### 6.1 快速路径优化

```
普通分配路径（无优化）
  │
  ▼
[likely/unlikely 优化]
  │
  └─► if (likely(!engine->enabled))  // 大概率未启用
         return;                         // 快速返回
  │
  ▼
  └─► if (unlikely(!strategy))       // 小概率为空
         return;
  │
  ▼
执行策略
```

### 6.2 per-CPU统计优化

```
统计更新（无锁，每CPU独立）

struct cpu_stats *s = this_cpu_ptr(&s_cpu_stats)  // 获取当前CPU的统计

s->alloc_count++                     // 无锁自增
